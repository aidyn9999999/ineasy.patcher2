# Перенос сайта и бота на VPS

Что получится: сайт `ineasy.site` и бот работают на одном сервере. Видео до 150 МБ принимаются через локальный Bot API, обрабатываются V2 и **сразу удаляются** после отправки. Redis остаётся в Upstash (данные пользователей никуда не переезжают).

## Какой сервер брать

**Hetzner Cloud CX33**, локация Германия (Falkenstein/Nuremberg) или Финляндия (Helsinki): 4 общих vCPU, 8 ГБ RAM, 80 ГБ NVMe, 20 ТБ трафика в месяц включено. Цена на момент написания около 8,49 € в месяц без НДС (плюс 0,50 € за IPv4); перед заказом сверьте цену и наличие на hetzner.com/cloud.

Расчёт: 15 000 пользователей — примерно 5 000 видео в день, в пик около 5 обработок одновременно. Видео не пережимается (ffmpeg `-c:v copy` + ADJN-патч), поэтому нагрузка идёт на сеть и память (~400 МБ на видео), а не на процессор. Исходящего трафика около 9–10 ТБ в месяц.

Настройки бота для этого сервера: `BOT_VIDEO_CONCURRENCY=3` (одновременно обрабатываются 3 видео, остальные ждут в очереди), `BOT_VIDEO_MAX_QUEUE=50` (длина очереди). Обработанное видео удаляется с диска сразу после отправки, поэтому 80 ГБ хватает с большим запасом.

Условия, на которые смотреть при заказе:
- **Только европейская локация.** В американских включён 1 ТБ трафика, в Сингапуре 0,5 ТБ.
- **Лимит расходов.** Hetzner считает только исходящий трафик сверх 20 ТБ (около 1 €/ТБ в Европе). Жёсткого лимита на сумму в панели я не нашёл: поставьте в Hetzner Console уведомление о расходах и следите за вкладкой Traffic у сервера. 15 000 пользователей укладываются в 20 ТБ с двойным запасом.
- **Рост:** тариф можно поднять в панели за пару минут без переустановки (по новой цене). При 30 000 пользователях трафик подойдёт к 20 ТБ — тогда CX43 или выделенный сервер.
- Гарантии «без задержек» у общих vCPU нет: на пике люди ждут в очереди. Если очередь часто растёт, поднимайте `BOT_VIDEO_CONCURRENCY` (по 400 МБ RAM на видео) или тариф.

Подойдёт Ubuntu 24.04; инструкция ниже для неё.

## Шаги

1. **Купить сервер.** В Hetzner: Cloud → создать проект → Add Server → локация в Европе → образ Ubuntu 24.04 → нужный тариф (shared vCPU подходит) → добавьте свой SSH-ключ (`ssh-keygen`, публичный ключ `~/.ssh/id_ed25519.pub`) → Create. Запишите IP-адрес.
2. **Подключиться:** `ssh root@IP`.
3. **Установить Docker:**
   ```bash
   curl -fsSL https://get.docker.com | sh
   ```
4. **Закрыть лишние порты:**
   ```bash
   ufw allow OpenSSH && ufw allow 80 && ufw allow 443 && ufw --force enable
   ```
5. **Скачать код:**
   ```bash
   git clone https://github.com/aidyn9999999/ineasy.patcher2.git && cd ineasy.patcher2
   ```
6. **Создать `.env`** (`nano .env`) — скопируйте все переменные из Railway → Variables и добавьте:
   ```
   NODE_ENV=production
   SITE_URL=https://ineasy.site/app.html
   TELEGRAM_API_ID=...        # с my.telegram.org
   TELEGRAM_API_HASH=...
   BOT_VIDEO_MAX_MB=150
   BOT_VIDEO_CONCURRENCY=3    # одновременно 3 видео, остальные в очереди
   BOT_VIDEO_MAX_QUEUE=50
   SERVER_PROCESSING=1        # включает обработку видео в боте; по умолчанию выключено (режимы V1/V2 на сайте работают всегда)
   ```
   Не задавайте `BOT_VIDEO_KEEP_DIR`, `BOT_API_ROOT`, `PORT`, `RAILWAY_*`.
7. **Остановить Railway** (Settings → Remove/Pause service), чтобы он не держал webhook бота.
8. **Один раз «выписать» бота из облачного Bot API:** откройте в браузере `https://api.telegram.org/bot<BOT_TOKEN>/logOut` (должно ответить `ok: true`). После этого подождите около 10 минут.
9. **Перенаправить домен:** в DNS у регистратора замените A-записи `ineasy.site` и `www` на IP сервера. Если для домена задан CAA, разрешите Let's Encrypt.
10. **Запустить:**
    ```bash
    docker compose up -d --build
    docker compose logs -f app
    ```
    В логах должно появиться «Бот слушает через вебхук». Caddy сам получит HTTPS-сертификат, когда DNS обновится.
11. **Проверить:** откройте https://ineasy.site, войдите через Telegram, отправьте боту видео 50–100 МБ и напишите `/disk`.

## Обслуживание

- Обновить код: `git pull && docker compose up -d --build`
- Логи: `docker compose logs -f app`
- Перезапускается сам после сбоя и после перезагрузки сервера (`restart: unless-stopped`).
- Место и память: `/disk` в боте, `df -h` и `docker stats` на сервере.
