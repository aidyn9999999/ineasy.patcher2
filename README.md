# Патчер видео — сайт с авторизацией через Telegram

Готово: авторизация через бота @ineasy_4k_bot, обработчик видео с локальным
патчингом метаданных в браузере, а также
прямая публикация в TikTok через личный Zernio API-ключ пользователя.

## Как это работает

1. Пользователь заходит на сайт и жмёт «Войти через Telegram».
2. Сайт создаёт 30-минутную login-сессию в Redis и открывает бота по ссылке `t.me/ineasybot?start=SESSION_ID`.
3. Пользователь жмёт «Запустить» в Telegram — бот проверяет подписку на `@ineasynews`.
   Если подписки нет, он предлагает подписаться и проверить ещё раз.
4. Сайт опрашивает сервер раз в 2 секунды и переводит пользователя на `/app.html`
   только после подтверждённой подписки.
5. На странице обработчика в правом верхнем углу показывается Telegram ID,
   а в центре — зона «Ставьте сюда ваше видео» (drag-and-drop или клик).
   Файл обрабатывается локально в браузере без отправки исходника на сервер.
6. После обработки видео можно скачать файл или сразу опубликовать его в личном TikTok-аккаунте через Zernio.

## Как подключить своего бота и токен

1. Напишите **@BotFather** в Telegram → `/newbot` (если бота ещё нет) или используйте
   существующего **@ineasy_4k_bot**.
2. Получите токен вида `123456789:AAExxxxxxxxxxxxxxxxxxxxxxxxxxxxxx`.
3. Скопируйте `.env.example` в `.env`:
   ```
   cp .env.example .env
   ```
4. Откройте `.env` и вставьте токен и переменные:
   ```
   BOT_TOKEN=123456789:AAExxxxxxxxxxxxxxxxxxxxxxxxxxxxxx
   BOT_USERNAME=ineasy_4k_bot
   NEWS_CHANNEL_ID=@ineasynews
   PORT=3000
   UPSTASH_REDIS_REST_URL=...
   UPSTASH_REDIS_REST_TOKEN=...
   SITE_URL=https://ineasy.site/app.html
   ```

5. Добавьте бота администратором канала `@ineasynews`. Это необходимо для проверки
   статуса подписки через Telegram Bot API. `NEWS_CHANNEL_ID` можно не задавать,
   если используется канал `@ineasynews`.

## Запуск

```bash
npm install
npm start
```

Сайт поднимется на `http://localhost:3000`, а бот начнёт слушать команду `/start`
через long polling — отдельный вебхук настраивать не нужно.

## Публикация в TikTok

После обработки нажмите «Пост в сайте (легкий)». В появившемся ниже разделе вставьте API-ключ Zernio; если ключа ещё нет, нажмите «Получить API-ключ», войдите в Zernio и создайте его в разделе API keys. Аккаунт TikTok должен быть привязан к этому ключу в Zernio. Ключ проверяется сервером и хранится в Redis только в зашифрованном виде. Ключ шифрования выводится из `BOT_TOKEN`, поэтому при смене токена бота пользователям потребуется подключить Zernio повторно.

Для возврата Zernio используйте `SITE_URL=https://ineasy.site/app.html`. Форму публикации можно открыть только после того, как ключ уже связан с аккаунтом TikTok в Zernio.

При публикации в конец описания автоматически добавляется `@ineasybot или ineasy.site(веб сайт)` и `#ineasybot`; в поле редактора эти строки не отображаются. В форме есть варианты видимости «Все», «Друзья» и «Только я», переключатели комментариев, дуэта и Stitch, отметка ИИ-контента и выбор публикации сейчас или по расписанию. Для расписания сайт передаёт Zernio `scheduledFor` и часовой пояс браузера. Перед отправкой пользователь подтверждает права на видео/музыку, проверку авторских прав и правила TikTok. Zernio/TikTok могут отклонить вариант приватности, недоступный для подключённого аккаунта.

Видео передаётся через серверный прокси по подписанному URL Zernio и не записывается на диск Railway. API-ключ не сохраняется в `localStorage` и не передаётся TikTok напрямую. Списание лимитов и баланс привязаны к Telegram ID и хранятся в Redis; авторизационные запросы проверяются серверной HMAC-подписью.

Для публикации Zernio-аккаунту требуется активное подключение TikTok и разрешение `video.publish`. Если ключ Zernio отозван, замените его в окне автопоста. Старые `SHORTSYNC_API_KEY` и `SHORTSYNC_CONNECTION_ID` больше не используются.

Все видео обрабатываются локально в браузере — отдельный сервер для перекодирования не используется. Для кадровой частоты применяется реальное преобразование в 59,94 FPS (60000/1001), а не простое изменение метаданных. HDR10/PQ и HLG направляются в локальный 10-битный HEVC-путь; перед выдачей проверяются частота кадров, разрешение и HDR-сигнализация. Dolby Vision с динамическими метаданными не перекодируется этим путём, поскольку обычное перекодирование не сохраняет динамические метаданные гарантированно. Сам ADJN-патчер работает с метаданными и не выполняет дополнительное сжатие видеопотока. При необходимости изменения FPS неизбежно повторное кодирование, поэтому оно может немного изменить размер и качество; если исходник уже 59,94 FPS, FFmpeg-путь сохраняет исходный видеопоток без повторного кодирования. TikTok может перекодировать видео после загрузки.

Для локального теста патчера установите Node.js и запустите статическую раздачу без backend и Telegram-бота:

```bash
npx --yes http-server public -p 4173
```

Откройте `http://localhost:4173/app.html?patcher-test=1`. Этот режим работает только на localhost, не требует входа и не списывает баланс. Видеообработка локальная; повторное кодирование не выполняется.

В Telegram меню покупки называется «Купить видео», проверка ссылок TikTok — «Проверка видео». Кнопка инструкции убрана из основного меню; справка доступна командой `/website`. После выбора пакета бот показывает сумму и реквизиты, просит настоящий чек и сообщает о ручной проверке администратором в течение 1–2 часов.


## Обработка видео прямо в Telegram-боте (режим V2)

Отправьте боту видео (до 150 МБ, файлом или как видео) — он сразу обработает его настройками V2 и вернёт файл `*-ineasy.mp4`. Выбирать режим не нужно: V2 зашит в код (`v2-engine.js`: ffmpeg stream-copy с проверкой FPS/разрешения/HDR + ADJN-патч, те же файлы `public/adjn-*.js`, что и на сайте). Тот же движок использует эндпоинт сайта `/api/v2/ffmpeg-copy`.

- Условия те же, что на сайте: подписка на `@ineasynews` и положительный баланс; одно видео списывается только после успешной отправки результата.
- Диск: всё хранится в временной папке задачи и удаляется сразу после отправки (и при старте сервера). По умолчанию обрабатывается одно видео за раз (`BOT_VIDEO_CONCURRENCY`), остальные ждут в очереди. Пик на диске — около 3× размера видео.
- **Лимит 20 МБ у облачного Bot API.** Чтобы принимать до 150 МБ, нужен локальный [Bot API сервер](https://github.com/tdlib/telegram-bot-api): запустите его с `--local`, один раз выполните `logOut` у бота на облачном api.telegram.org, укажите `BOT_API_ROOT=http://<хост>:8081`. Если сервер Bot API на той же машине/томе, файлы просто переносятся без копирования; иначе скачиваются по HTTP. Без `BOT_API_ROOT` бот принимает только видео до 20 МБ.
